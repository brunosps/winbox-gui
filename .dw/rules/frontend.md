## Patterns to Follow

### Escape Before Template Injection

Dynamic strings rendered into template HTML are escaped via `escapeHtml` and
`escapeAttr`. Keep using these helpers whenever a backend, profile, bundle,
GPU, snapshot, or user-entered value is interpolated into `innerHTML`.

**Example from codebase:**

```js
// From: src/dom-utils.js
const HTML_ESCAPES = {
  "&": "&amp;",
  "<": "&lt;",
  ">": "&gt;",
  '"': "&quot;",
  "'": "&#39;",
};

export function escapeHtml(value) {
  return String(value ?? "").replace(/[&<>"']/g, ch => HTML_ESCAPES[ch]);
}
```

### Lightweight i18n

Text should be addressed through keys in `src/locales/*.js`, with fallback to
`en-US` and then to the key. DOM-wide static text uses `data-i18n`.

**Example from codebase:**

```js
// From: src/i18n.js
export function t(key, vars = {}) {
  const primary = bundles[current] || {};
  const fallback = bundles["en-US"] || {};
  let str = primary[key] ?? fallback[key] ?? key;
  for (const [k, v] of Object.entries(vars)) {
    str = str.replace(new RegExp(`\\{${k}\\}`, "g"), String(v));
  }
  return str;
}
```

## Request Flow Examples

4. **Render:** `dashboardShell()` creates rows and detail panel

## Anti-patterns to Avoid

### Remove Flow Bypasses Its Specialized Dialog

- **Severity:** High
- **Found in:** `src/main.js:690`, `src/main.js:914`, `src-tauri/src/lib.rs:603`
- **Issue:** `removeProfileDialog()` supports a delete-storage checkbox, but the action handler uses generic `confirmDialog()` and then calls `remove_profile`, whose backend currently passes `delete_storage = true`.
- **Risk:** users have no UI path to preserve a custom storage directory despite the specialized dialog existing.
- **Recommendation:** wire the remove action to `removeProfileDialog()`, pass `deleteStorage` through the Tauri command, and keep the backend default explicit.

### E2E Selectors Drifted From Current Markup

- **Severity:** Medium
- **Found in:** `tests/e2e/specs/smoke.spec.mjs:31`, `src/main.js:446`, `src/main.js:556`
- **Issue:** the smoke test queries `.profile-card` and `.empty-state`, while current rendered markup uses `.profile-row` and `.table-empty`.
- **Risk:** E2E can fail for selector drift unrelated to product behavior.
- **Recommendation:** update smoke selectors or add stable `data-testid` / role-based selectors.

### Large UI Controller File

- **Severity:** Medium
- **Found in:** `src/main.js` (~1734 lines)
- **Issue:** one file owns most frontend workflows.
- **Risk:** unrelated features collide and regressions are harder to test.
- **Recommendation:** continue the existing helper pattern (`profile-display.js`, `dom-utils.js`) for new pure logic.

### Inline HTML Rendering Requires Discipline

- **Severity:** Medium
- **Found in:** `src/main.js`
- **Issue:** many templates use `innerHTML`.
- **Risk:** a missed escaping call can introduce XSS-like behavior inside the local WebView.
- **Recommendation:** keep all dynamic values escaped via `escapeHtml`/`escapeAttr`; add tests for any new formatter.
