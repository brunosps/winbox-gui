## Architecture

Rust is organized as a Tauri command boundary plus domain modules. `lib.rs`
exposes serializable command contracts, emits progress events, and pushes
blocking work onto Tauri's blocking runtime. `commands/` contains high-level
profile operations, while `core/` contains reusable infrastructure and domain
helpers for Docker, Compose generation, profiles, validation, health, GPU/VFIO,
snapshots, bundles, and paths.

## Request Flow Examples

### Launch Profile

1. **Entry:** frontend calls `launch_profile`; handler is in `src-tauri/src/lib.rs`
2. **Validation/resolve:** `profile::resolve(Some(&name))`
3. **Preflight:** Docker/KVM checks in `core::docker`
4. **Business logic:** `commands::launch::ensure_started`
5. **Readiness:** `wait_for_web_port` after recreated containers
6. **Response:** default browser opened to noVNC URL and `OperationResult` returned
7. **Error path:** `LaunchError` variants serialize to frontend-friendly structured errors

### Install Profile

1. **Entry:** `install_profile` Tauri command
2. **DTO mapping:** `InstallArgs` -> `commands::install::InstallParams`
3. **Validation:** profile name, family args, env fields, resources, storage path, GPU BDF
4. **Data write:** `config.env`, chmod `0600` on Unix, generated `compose.yml`, optional OEM scripts
5. **Runtime:** Docker Compose `up -d`
6. **Response:** `OperationResult`
7. **Error path:** `anyhow` context converted to string and emitted as failed progress

### Snapshot Rollback

1. **Entry:** `rollback_snapshot` Tauri command
2. **Validation:** `profile::resolve`, `validate_snapshot_name`
3. **Business logic:** `snapshots::rollback`
4. **Data operation:** stop container if needed, replace storage directory with sparse copy from snapshot
5. **Response:** operation progress success and message
6. **Error path:** invalid/missing snapshot bails; failed copy bails

## Anti-patterns to Avoid

### Large Boundary and CLI Files

- **Severity:** Medium
- **Found in:** `src-tauri/src/lib.rs` (~901 lines), `src-tauri/src/cli.rs` (~627 lines)
- **Issue:** IPC/CLI boundary files carry many unrelated command flows.
- **Risk:** new command logic can accumulate in boundary files instead of in `commands/`/`core/`.
- **Recommendation:** keep boundary files thin: DTO mapping, progress events, and delegation only.

### Destructive Best-effort Cleanup Is Silent

- **Severity:** Medium
- **Found in:** `src-tauri/src/commands/lifecycle.rs`
- **Issue:** several cleanup paths intentionally ignore errors (`compose down`, `rm_force`, desktop regenerate, custom storage removal).
- **Risk:** operational cleanup failures can be hidden from users.
- **Recommendation:** keep best-effort behavior only where product semantics require it; emit progress or warnings for user-actionable failures.

### Env Parser Is Deliberately Simple

- **Severity:** Low
- **Found in:** `src-tauri/src/core/env_file.rs:13`
- **Issue:** config parsing is `split_once('=')`, with no quoting or escaping semantics.
- **Risk:** values containing newlines are rejected elsewhere, but complex shell-like env syntax is not supported.
- **Recommendation:** preserve simple `KEY=value` contract; do not add shell-env features casually.

### Large Core Integration File

- **Severity:** Medium
- **Found in:** `src-tauri/src/core/docker.rs` (~946 lines)
- **Issue:** Docker client, compose execution, pull progress parsing, error classification, and mocks live together.
- **Risk:** high blast radius for launch/update regressions.
- **Recommendation:** when changing Docker behavior, cover both real command construction and parser/classifier tests.
