# winbox-gui — Architecture

## Purpose

GUI + CLI for managing **Windows and Linux VMs** running inside the `dockurr/windows` and `qemux/qemu` Docker images. Wraps `docker compose` lifecycle, exposes RDP (Windows) and noVNC (Linux) connect paths, supports GPU passthrough via VFIO.

## Profile model

Each profile lives at two paths:

- **Config**: `~/.config/winbox/profiles/<name>/`
  - `config.env` (0o600) — IMAGE_FAMILY, BOOT/VERSION, USERNAME, PASSWORD, RAM/CPU/DISK, ports, GPU_BDF, etc.
  - `compose.yml` — generated by `core::compose::write`, references the env file.
  - `oem/` — Windows-only `install.bat` + `firstlogon.ps1` generated from selected bundles.
- **Data**: `~/.local/share/winbox/profiles/<name>/`
  - `storage/` — Docker volume with disk image + UEFI vars + ROM.
  - `snapshots/` — qcow2 snapshots.

Containers are named `winbox-<profile>`. Compose project label is also `winbox-<profile>` (see `core::docker::compose_run`).

## Image family routing

`ImageFamily` (in `core::image_family`):

| Family | Image | Connect mode |
|---|---|---|
| Windows | `dockurr/windows:5.14` | RDP via xfreerdp3 |
| LinuxDistro | `qemux/qemu:7.29` | noVNC web UI |
| LinuxIso | `qemux/qemu:7.29` | noVNC web UI |

Image tags are pinned in `core::paths` (`IMAGE_WINDOWS`, `IMAGE_QEMU`).

`core::connect::resolve` always maps Linux → `WebVnc`. The Phase 2 plan (curated distros → RDP via cloud-init xrdp) is documented but not implemented.

## Launch flow

```
Tauri "launch_profile" → connect::resolve_for_profile
                       ├─ Rdp     → commands::launch::launch_rdp
                       │            → ensure_running (defensive rm_force stale)
                       │            → wait_for_windows (240s log marker)
                       │            → rdp::launch (xfreerdp3 + log to ~/.cache/winbox/)
                       └─ WebVnc → commands::launch::ensure_for_web_vnc
                                    → ensure_running
                                    → wait_for_web_port (60s TCP probe)
                                    → open_web_vnc_window (WebView at /?autoconnect=true)
```

Key invariants:

- `ensure_running` defensively removes any non-running/non-paused container (`docker rm -f`) before re-running `compose up -d`. This handles stale containers from earlier code versions or manual compose invocations.
- noVNC opens with `?autoconnect=true&resize=scale` — the default noVNC UI keeps `autoconnect=false` and idle without these.
- xfreerdp stdout/stderr are teed to `~/.cache/winbox/rdp-<profile>.log` so silent spawn failures become diagnosable.

## GPU passthrough

When `GPU_BDF` is set on a profile, `core::compose::build_gpu_block` adds:

- `/dev/vfio/vfio` + `/dev/vfio/<iommu_group>` devices.
- `cap_add: [SYS_ADMIN, IPC_LOCK]`.
- `ulimits: memlock: -1` (RAM pinning).
- QEMU args: `-cpu host,kvm=off,hv_vendor_id=whatever -device vfio-pci,host=<bdf>,multifunction=on` (Code 43 mitigation for GeForce).

`core::gpu_hooks::prepare_for_start` / `cleanup_after_stop` run at container start/stop transitions.

**Operational note**: With GPU passthrough active, the guest output goes to the **physical monitor connected to the passed-through GPU**. The noVNC channel (virtio-vga) shows "Display output is not active." This is by design.

## Testing

- **Rust**: `cargo test --manifest-path src-tauri/Cargo.toml` — 12 tests, mostly in `core::compose`, `core::validation`, `core::health`.
- **JS**: `node --test src/*.test.js` — 3 tests in `dom-utils.test.js` (escapeHtml, escapeAttr, cssToken).
- **Combined**: `npm run test`.
- **Build**: `cargo build --manifest-path src-tauri/Cargo.toml` or `npm run tauri build`.
- **No integration tests** for install→launch flow yet (stability work item).

## CLI

`src-tauri/src/cli.rs` mirrors the GUI command surface for scripted use. Entrypoint dispatcher is `src-tauri/src/main.rs`. `clap` parses subcommands; `dialoguer` handles interactive prompts when `--yes` is absent.

## Frontend

Vanilla JS (no framework). One HTML page, six modals (install, settings, logs, snapshots, reapply, confirm). `src/main.js` renders profile cards from `list_profiles`, dispatches actions via `cmdMap` (line ~857) to Tauri commands. i18n via `src/i18n.js` + `src/locales/{en-US,pt-BR}.js`. XSS-safe DOM helpers in `src/dom-utils.js`.

## Configuration paths (XDG)

| Purpose | Path |
|---|---|
| Profile configs | `~/.config/winbox/profiles/<name>/` |
| Profile data (disks, snapshots) | `~/.local/share/winbox/profiles/<name>/` |
| Shared host folders | `~/Windows/<name>/` |
| Desktop launchers | `~/.local/share/applications/` |
| RDP logs (new) | `~/.cache/winbox/rdp-<name>.log` |
