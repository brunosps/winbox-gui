# Architecture - winbox-gui

Generated by `/dw-intel --build` on 2026-05-28.

## Shape

winbox-gui is a Tauri 2 desktop app with a vanilla JavaScript frontend and a
Rust backend. The frontend in `src/main.js` renders the dashboard and invokes
Tauri commands. The Rust backend in `src-tauri/src/lib.rs` is the IPC boundary:
it maps frontend DTOs into `commands/*`, emits `operation-progress`, and pushes
blocking Docker/filesystem work to Tauri blocking threads.

## Layers

```text
src/main.js
  -> Tauri IPC command names
src-tauri/src/lib.rs
  -> src-tauri/src/commands/*
src-tauri/src/commands/*
  -> src-tauri/src/core/*
src-tauri/src/core/docker.rs / compose.rs / paths.rs
  -> Docker, Docker Compose, KVM, filesystem, browser opener
```

The Rust code mostly follows a command-orchestrator plus core-helper pattern.
`commands/` owns user-level operations such as install, launch, lifecycle,
set, logs, and reapply. `core/` owns reusable primitives for Docker, Compose,
validation, profile paths, config env files, snapshots, health, bootstrap, GPU,
and VFIO.

## Main Flows

Dashboard refresh calls `list_profiles` and `host_health`, then rebuilds the
workspace from frontend state. Profile launch calls `launch_profile`, resolves
the profile, checks Docker/KVM, ensures the container is running, waits for
noVNC when needed, and opens `http://127.0.0.1:<WEB_PORT>` in the default
browser. Profile install validates inputs, writes `config.env`, chmods it to
`0600` on Unix, writes `compose.yml`, optionally generates OEM scripts, then
starts Docker Compose.

## Runtime and Persistence

Profiles live under platform-specific config/data roots from
`src-tauri/src/core/paths.rs`. Generated Compose binds exposed VM ports to
`127.0.0.1`. Windows profiles use `dockurr/windows:5.14`; Linux profiles use
`qemux/qemu:7.29`. No database or ORM was detected.

## Risk Areas

`src/main.js`, `src-tauri/src/lib.rs`, `src-tauri/src/cli.rs`, and
`src-tauri/src/core/docker.rs` are large, high-blast-radius files. Stable core
helpers (`paths`, `docker`, `env_file`, `profile`) have many inbound users, so
changes there should be tested broadly. E2E selectors in
`tests/e2e/specs/smoke.spec.mjs` appear stale compared with current
`src/main.js` markup.
